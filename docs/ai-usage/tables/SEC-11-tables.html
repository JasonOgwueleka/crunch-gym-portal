Files changed (SEC-11, owner Alex)

FileWhat changed
server/src/utils/healthCrypto.js (new)AES-256-GCM field encryption using Node's built-in crypto. Random 12-byte IV per value; 16-byte auth tag. Format enc:v1:<keyId>:<iv>:<tag>:<ciphertext>. AAD binds each value to its member and field. Keys loaded and validated from HEALTH_DATA_KEY (+ optional key id and old keys for rotation). decryptForViewer() is used by routes after their permission checks; integrity failures are audited and never return garbage.
server/src/routes/health.jsThe 5 sensitive text fields are encrypted before INSERT/UPDATE. The member's own view, the assigned-trainer/admin view and the admin list decrypt only after the existing requireRole / assertCanViewMember checks.
server/src/routes/clients.jsThe trainer's client page decrypts the questionnaire only after assertTrainerOf().
server/src/index.jsThe server refuses to start (exit 1, clear message) if HEALTH_DATA_KEY is missing or not exactly 32 bytes.
server/scripts/seed.jsSeeded questionnaires are encrypted with the same function as the API. The seed refuses to run without the key. The test member now has synthetic medication and condition text so encryption is visible.
server/scripts/reencrypt-health.js (new)npm run db:reencrypt-health: encrypts any plaintext values and re-encrypts values from old keys with the current key (key rotation), in one transaction; safe to re-run.
server/package.json, package.jsonNew script db:reencrypt-health.
.env.example.env.example documents HEALTH_DATA_KEY (required), HEALTH_DATA_KEY_ID and HEALTH_DATA_OLD_KEYS. A real random key was generated into the git-ignored .env.local (never printed or committed).
security-tests/sec11-health-encryption.sql (new)SQL for T-11b (view ciphertext vs v0 plaintext) and T-11d (change one character).
