FileWhat changed
server/src/utils/session.js (new)Session helpers: startAuthenticatedSession (new session ID plus login and activity timestamps), destroySession (deletes the session server-side and clears the cookie), destroyAllSessionsForUser (deletes every stored session for a user).
server/src/middleware/auth.jsloadUser now enforces the idle timeout (15 min) and absolute timeout (8 h) on every request using timestamps stored in the session. An expired session is deleted, the response gets X-Session-Expired, the event is audit-logged, and protected routes return 401 with code SESSION_EXPIRED.
server/src/index.jsSession cookie flags: HttpOnly, SameSite=Strict (was Lax), Secure when NODE_ENV=production; cookie lifetime set to the absolute timeout.
server/src/config.jsNew settings SESSION_IDLE_TIMEOUT_MINUTES (default 15) and SESSION_ABSOLUTE_TIMEOUT_MINUTES (default 480 = 8 h), and cookieSecure (true when NODE_ENV=production).
server/src/routes/auth.jsLogin and registration now issue a brand-new session ID. Logout destroys the session server-side. Change-password and reset-password delete ALL sessions for the user, including the current one. Deleting your own account also deletes all your sessions.
server/src/routes/users.jsWhen an admin sets a new password for a user, all of that user's sessions are ended.
server/src/utils/http.jsHttpError can carry a machine-readable code (used for SESSION_EXPIRED).
client/src/lib/api.jsDetects an expired session on any response (X-Session-Expired header or SESSION_EXPIRED code) and notifies the app.

client/src/pages/public/AuthPages.jsxLogin page shows the notice (e.g. 'Your session expired because you were inactive. Please log in again.').
client/src/pages/shared/Profile.jsxAfter a password change the user is logged out and sent to the login page with a message.
